    第九讲 · 期货面板五坑：把第三章的方法论走一遍完整流程¶

    第三章 · 数据口径的暗雷（第三讲，本章收尾） 学习目标：通过期货面板的五个真实缺陷，演练"发现→定位→裁定→处置"的完整口径审计流程；理解"战役继续 vs 停止"的决策标准。 前置：第七、八讲。

    0. 引言¶

    前两讲各深挖了一颗雷。这一讲换个模式：把期货面板的五颗雷放在一张桌上，每颗按同一套流程过——症状、根因、影响面裁定、处置决策。目的不是记这五个坑（换了数据商坑会变），而是把口径审计的标准动作练成肌肉记忆。

    五坑速览：

    # 坑 类型 影响面 战役决策
    1 双重复权 收益构造错误 跨换月持有的策略（carry 全灭） 面板重建（第七讲详述）
    2 夜盘日期戳错位 时间戳约定 跨源 join、日历对齐 收益按品种行序重算，战役继续
    3 换月跳空未处理 拼接 artifact 趋势/突破类因子假信号 检测工具 + 因子层规避
    4 $oi 覆盖勘误 元数据认知错误 引用持仓量的因子解释权 认知修正，标注留痕
    5 面板末端越界 基础设施边界 回测崩溃/静默截断 测试窗回退一交易日

    1. 坑二：夜盘日期戳错位——一个"不修数据"的决策¶

    症状：918 天的面板里混着 180 个"周日"行。日历上期货夜盘属于次一交易日，但数据商在数据落盘时按夜盘开盘的实际挂钟时间盖章——周日晚 21:00 开的夜盘，被盖成周日的日期。

    根因：不是数据错误，是时间戳约定（vendor 用挂钟时间，研究用交易日历）。两套约定各自自洽，混用才出错。

    关键裁定：逐项检验后发现—— - 收益序列是对的：每个品种的行序（row order）正确，按行序差分算收益没有任何问题 - 错位只发生在跨源 join：拿这张面板的日期去 join 另一张按交易日历盖章的表（如持仓量表），日期整体错一天

    处置：不修数据（重盖日期戳有引入新错误的风险），改用法——收益一律按品种行序计算；跨源 join 一律先做日期对齐校验。战役继续，零中断。

    这一坑的教学点是审计的"影响面裁定"步骤：发现约定不一致时，先问哪些下游计算被感染、哪些天然免疫，再决定修数据还是改用法。盲目重修面板，可能把一个无害的约定差异变成真正的错误。

    2. 坑三：换月跳空——artifact 与信号的分界¶

    症状与根因：主力连续拼接处，若复权不彻底（或刻意保留原始价差），换月日产生价格跳空。这个跳空是拼接 artifact，不是市场信息——但趋势、突破类因子不区分二者：一次假跳空 = 一次假突破信号 = 一笔假交易。

    处置的分层设计： 1. 检测工具：换月检测器——按持仓量单日跳变（|Δoi| ≥ 30%）或开盘跳空（|gap| ≥ 3%）的启发式扫描，输出每个品种的换月日清单 2. 因子层规避：涉及突破逻辑的因子在换月日窗口内不触发 3. 不做的事：不去"修复"跳空本身——趋势研究有时恰恰需要真实价差信息，全局抹平是过度处理

    教学点：artifact 的正确处置是"识别 + 隔离"，不是"消灭"。数据清洗的过度执行和执行不足同样危险，分界线就在"这个特征对哪类研究是噪声、对哪类是信息"。

    3. 坑四：$oi 覆盖勘误——认知勘误比数据勘误更常见¶

    症状与根因：研究文档长期记载"持仓量列 $oi 部分品种缺失"。一次系统核查发现：全覆盖——此前的"部分缺失"是早期一次抽样检查的误读，被当作事实写进了文档并流传。

    危害机制：这条错误认知让若干研究方向被提前排除（"持仓量因子做不了全品种截面"），也给某些因子结果提供了错误的豁免解释（"表现差是因为 oi 缺数据"）。错误的数据可以复算纠正，错误的"关于数据的认知"只会静默地扭曲研究选择——后者从不出现在任何代码里。

    处置：认知修正 + 文档勘误留痕；被错误排除的方向重新进入机会清单评估。

    教学点：审计对象不只是数据，还有数据字典/覆盖说明/口头共识。定期用脚本实测"文档声称的数据属性"（覆盖率、起止日、空值率），实测与声称不符处即为勘误候选。

    4. 坑五：面板末端越界——基础设施边界也要预注册意识¶

    症状：qlib 回测器在最后一步读取 calendar[i+1]（结算需要 T+1 的日历）。测试窗末端贴着面板末日时直接越界崩溃。

    裁定：这是工具的硬边界，不是策略问题。但它的危险变种是静默版：某些环境下不崩溃而截断最后一段——回测少算几天，数字略变，无人察觉。

    处置：约定测试窗末端距面板末日 ≥1 个交易日（实战实测后写入配置默认值）。教学点：基础设施的边界条件应当写进实验规范，和统计门槛一样显式——"回测窗口的合法取值域"也是预注册文档应有的一节。

    5. 收束：口径审计的标准流程¶

    五坑走完，提取公共流程——这是第三章的最终交付物：

    ① 症状     异常数字 / 崩溃 / 交叉对账不一致 / 文档与实测不符
② 根因     数据错误? 约定差异? artifact? 认知错误? 工具边界?
③ 影响面   哪些下游被感染、哪些免疫（差分 vs 水平、行序 vs 日期、
           跨换月 vs 短周期……按第七讲"接触面"原则排优先级）
④ 裁定     修数据 / 改用法 / 隔离 artifact / 修正认知 / 只写规范
⑤ 处置     执行 + 勘误编号留痕 + 历史结论重述（不改历史文档，只限定效力范围）
⑥ 下游     受影响的预注册：功效重估、门槛复核、必要时撤回（第七讲）

    以及三条贯穿第三章的元原则：

    1. 审计优先级与结果的"合理性"正相关，而非负相关（第七讲：错得好代价大）
    2. 修数据是最后手段——约定差异改用法、artifact 做隔离、认知错误改文档（第九讲五坑里只有双重复权真正触发了面板重建）
    3. 勘误必须留痕且不篡改历史——旧文档标注收窄、新结论按勘误后数字重述，让历史永远可复算（这是 D-9 能被纠正的制度前提）

    6. 第三章总结¶

    • 五坑覆盖五种失效类型：构造错误、约定差异、拼接 artifact、认知错误、工具边界
    • 审计六步流程：症状→根因→影响面→裁定→处置→下游
    • 判定"战役继续还是停止"的标准：核心收益序列的正确性（坑二裁定后战役继续；坑一动摇收益地基，面板重建）
    • 口径审计不是入门功夫而是持续义务——五坑中四个是战役中途才被发现的

    第二章建立了一个诚实的验证制度；第三章证明了这个制度的地基（数据与量的定义）本身需要同等级的审计。第四章转向最终问题：当一切验证都通过之后，一个活下来的策略要经历什么才能上线——以及为什么"上线"依然不是终点。

    思考题：坑二（日期戳约定）中"不修数据、改用法"的决策，依赖"所有下游都改为按行序计算"这一纪律。如果半年后新加入的研究员不知道这个约定，按日期 join 了一张外部表——用什么机制能保证这类"约定"不随人员流动而丢失？（提示：对比"写在文档里"和"写进代码里"两种方案的失效模式。）
