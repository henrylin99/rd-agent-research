# 番外二 · HITL 侦察屏：把人放进循环的另一种方式

> 番外篇（建议先读第六讲与第十二讲）
> 学习目标：理解人机回圈（HITL, Human-In-The-Loop）侦察模式的设计逻辑，及其与全自动循环的互补关系。

## 1. 背景：为什么需要一个"人填的屏"

主课的全流程（工厂→验证→影子）有一个隐含适用范围：**假设可以完全形式化、可以用历史数据回测**。但有一类机会不满足这个前提：

- 信号是**非结构化**的（新闻、公告、传闻的定性判断）
- 出现频率低（一年就几十次有效事件），历史样本不够回测
- 判断本身依赖人的语境理解，难以预先写成规则

对这类机会，硬塞进回测框架是削足适履；放弃又可惜。第三种方案：**侦察屏**——系统负责扫和记，人负责判和填，判定结果沉淀为前向数据。

## 2. 设计：冻结在先

真实落地的 HITL 扫描器（2026-09-27 上线，判定日 2026-12-26）关键设计决策：

**① 预注册纪律同样适用。** 判定指标（precision ≥ 30%、填报率 ≥ 50%）和判定日在上线前冻结——第十二讲的闸门制度原样搬过来。人机回圈不是纪律豁免区：恰恰因为有人参与，"顺手调一下标准"的诱惑更大。

**② 人的判断被结构化。** 填报界面只接受离散字段（方向、置信档、理由码），不接受自由文本打分——保证 90 天后的数据可统计。自由发挥的判断无法聚合。

**③ 判定日覆盖真实事件轮。** 屏幕监控指数调样事件，判定日定在 2026-12 调样轮之后——让判定发生在"屏幕见过至少一轮完整真实事件"之后，而不是凑够日历天数。

**④ 90 天观察，中途不看结果。** 与 OOS 一次性判定同构：中途偷看→知道哪类信号表现好→下意识改变填报行为→数据被污染。人在循环里，人就是最大的自由度来源，所以锁得要更死。

## 3. HITL 与全自动循环的分工

| | 全自动循环 | HITL 侦察屏 |
|---|---|---|
| 假设形式 | 可形式化、可回测 | 定性、低频、依赖语境 |
| 人的角色 | 定面板/口径/门槛 | 在循环内做判断 |
| 数据产出 | 历史回测 | 前向积累的结构化判断流 |
| 判定 | 预注册 OOS 一次判定 | 预注册指标 + 冻结判定日 |
| 主要风险 | 多重检验 | 人的行为漂移污染数据 |

两者共享的不是技术，是纪律骨架：**冻结判据、积累前向数据、一次性判定**。区别只在数据从哪来（回测 vs 人的判断流）。

## 4. 本番外小结

- HITL 的适用区：不可回测形式化、低频、依赖语境的机会
- 结构化填报 + 冻结判据 + 覆盖完整事件轮 + 中途不看结果——四件套把人的自由度锁在数据质量允许的范围内
- 全自动与 HITL 是同一套验证纪律的两个数据来源

**思考题**：判定指标里的"填报率 ≥ 50%"为什么是必要条件？（提示：如果只有 10% 的信号被填了判断，precision 再高，这个屏作为数据资产的价值是什么？——选择性填报本身就是一种事后选择偏差。）
