# 第七讲 · D-9 勘误：一个复权 bug 如何制造出年化 18% 的假策略

> 第三章 · 数据口径的暗雷（第一讲）
> 学习目标：理解期货主力连续合约的复权机制与"双重复权"bug 的成因；掌握"数字合理性偏差"这一概念；理解勘误的制度化处理。
> 前置：第二讲（carry 因子首次出场处）、第四讲（预注册制度）。

## 1. 案例概述

期货第二轮战役的研究矩阵里有一条 L2 线：期限结构 carry 策略（做多贴水深的品种、做空升水高的品种，赚取价差收敛）。工厂的发现期回测给出：

> **发现期年化 +18%，全战役最亮眼的数字，t 值漂亮，分年结构合理。**

九天后（编号 D-9 的勘误事件），审计发现面板构建存在**双重复权**。纠错后重算：

> **发现期 +3.18%，t = 0.66，统计上与零无异。**

一个数字从"接近可部署"跌到"噪声"，中间只隔一次口径审计。这个数字本身值得讲九天，但更值得讲的是：**它为什么差点骗过所有人——包括一条本来很严格的验证制度。**

## 2. 技术背景：主力连续合约与复权

期货没有股票那样的单一连续代码。做面板时通常取"主力连续"：每个月份合约到期后切换到新的主力，把各段拼接成一条连续序列。拼接点（换月日）两个合约价格不同（升贴水），直接拼会产生假跳空——于是需要**复权**：在换月日对历史序列做整体平移或比例调整，消除拼接缺口。

本战役面板用的是**结算价衔接复权**：以结算价为锚做衔接。

**双重复权 bug 的机制**：构建管线里有两处各自独立地对换月缺口做了调整（一处是显式的复权步骤，一处藏在收益序列的构造里）。两次调整叠加，效果是**每次换月都朝同一个方向多修正了一点**。23 个品种 × 四年 × 每年若干次换月，误差不是随机噪声，而是**系统性单向漂移**。

这是关键：随机噪声会互相抵消，让 t 值变难看；**系统性偏差同向累积，让 t 值变好看**。carry 策略天然持有多空两侧、持有期跨越换月日——它把这个单向漂移完整地吃进了收益里。

## 3. 为什么它差点骗过所有人：数字合理性偏差

这是本讲最想留给你的概念。+18% 为什么没在第一时间被怀疑？

因为**它看起来太合理了**。期限结构 carry 在文献里有先例（商品 carry 是经典的 risk premium），"年化 18%"落在"这个策略本来就该赚钱、而且赚得不少"的预期区间内。人检查数字时的心理默认是：**离谱的才查，合理的放过**——而一个高质量的 bug，产出恰恰是合理的数字。

对照一个思想实验：如果同样的管线错误让 carry 的回测显示**年化 −25%**，它活不过当天下午——太离谱，一定有人去查。方向反的 bug 是自我暴露的，方向对的 bug 是自我隐藏的。

> **数字合理性偏差**：数字与先验预期的一致性，会被误用作"数字正确性"的证据。二者独立——bug 不懂金融，它只是恰好朝你希望的方向歪了。

推论：对一个**特别符合预期的结果**，审计优先级应该**上升**而不是下降。这违反直觉，但逻辑成立：好结果获得部署，坏结果只获得忽略——错得好代价大，错得坏代价小。

## 4. 勘误是怎么发生的：制度而不是灵感

这个 bug 不是被"看出来"的，是被**流程逼出来**的。触发链：

1. **独立复算要求**：L2 线进入正式验证前，验证管线规定收益序列必须从原始数据独立重算，不消费工厂面板的现成收益列
2. **交叉对账**：独立重算结果与工厂面板对不上——差异集中在换月日附近
3. **根因定位**：两条代码路径对比，找到重复调整的那一步
4. **勘误执行**：面板重建、全部历史结论按"纠错后数字"重述、勘误文档编号存档（D-9）

注意第 1 步——它正是第四讲"构件一：独立数据复算"的实例。如果验证管线直接消费工厂面板，这个 bug 会被永久继承，carry 会带着假年化 18% 一路走进影子监控。

**留痕的二次价值**也在此体现：因为旧结论可以复算，勘误才能"重述历史"而不是"重新开始"——+18% 被改写为 +3.18%，而不是悄悄删掉。

## 5. 勘误之后的连锁处置（比勘误本身更重要）

发现 bug 只是开始，一个诚实的体系要处理它的**全部下游**：

| 处置 | 内容 | 逻辑 |
|---|---|---|
| 协议修订 | 研究协议版本化（v1.0 + D-9 修订），勘误记录在案 | 规则变更必须留痕，防止"改了就当没发生" |
| 功效撤回 | 原定 OOS 判定门槛基于 +18% 的预期量级；纠错后 +3.18% 对应的统计功效极低（350 日窗、正态近似下约 7%）——原门槛实际上**判不动** | 门槛是为大效应设计的，效应缩水后门槛失效，继续用等于形式主义 |
| 优先级降级 | L2 从主攻线降为低优先级观察线 | 效应可能存在但太小，不值得主攻投入 |
| 暂停部署投入 | 明确规定：即便后续 OOS ≥10% 也不单独触发部署 | 防止"纠错后急于翻盘"的心理把小效应重新放大 |
| 审计标注收窄 | 早期审计文档的适用范围收窄标注（粗略诊断、不含换月），历史数字零改动 | 勘误不篡改历史文档，只限定其效力范围 |

其中"功效撤回"最值得展开：预注册门槛（比如"OOS 年化 ≥X% 且 p<0.05"）隐含一个假设——效应量级足够大，使得可用样本量下检验有足够功效。当效应从 18% 缩到 3.18%，同样的门槛配上同样的窗口，真效应也几乎判不出 SUPPORTED。**继续执行一个没有功效的检验，结果无论是什么都没有信息量**（ACCEPT 是运气，REJECT 也不说明问题）。诚实的处理是承认"这个问题在当前数据量下不可判定"——这正是第六讲 INCONCLUSIVE 判决在另一个维度的重现。

## 6. 本讲小结

- 双重复权 = 换月调整被执行两次，误差系统性同向累积，恰好喂给跨换月持有的 carry 策略
- 系统性偏差让 t 值变好看；随机噪声让 t 值变难看——**好看的数字未必更干净**
- 数字合理性偏差：结果越符合预期，越容易被放过审计；纠正是对符合预期的结果提高审计优先级
- 勘误的下游四件套：协议版本化、功效撤回、优先级降级、历史标注收窄
- 独立复算是捕获此类 bug 的唯一制度性手段

**思考题**：假设双重复权 bug 影响的不是 carry（多空两侧跨换月持有），而是一个 3 日短周期反转策略（持仓不过换月日）。它受到的污染会更重还是更轻？这提示了什么审计原则？（提示：偏差的空间分布决定哪些策略吃进多少——审计要按"策略与缺陷机制的接触面"排优先级，而不是按策略的收益排名。）
